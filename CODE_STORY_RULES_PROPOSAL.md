# CODE_STORY_RULES

Код читається як розповідь: послідовність, сюжет, сенс у кожній змінній і в кожному імені.
Каскад s1 → s2 існує для того, щоб розповідь була написана ДО коду, а переклад у C# нічого не
вигадував. Правила форми стоять рівнем нижче: вони ловлять те, чого розповідь не має.

```clojure
(def standing

   :history "останній прогін каскаду — Flows/Archive/FLOW_CASCADE_S2_LAKE.md; FLOW_CASCADE_S1_REDESIGN не зберігся"})
```

```clojure
(def cascade
  {:goal      "розповідь написана ДО коду; переклад у C# нічого не вигадує"
   :artifacts [s1 s2]
   :s1        "постановка задачі та алгоритм її вирішення: що робимо, за яким правилом, якими структурами і що кожен крок у них міняє"
   :s2        "стиснений псевдокод майбутнього класу: декомпозиція на методи, час життя структур, напрям кожного значення"
   :code      "переклад s2 — і тільки переклад"
   :law       "s1 не знає імен методів і класів — лише типи даних; декомпозиція народжується вперше в s2; у коді нема нічого, чого нема в s2"
   :s1-is-not "менш детальна копія s2: якщо в s1 видно майбутні методи, обговорювати алгоритм уже пізно"
   :back-to-s2 "потреба, яку виявив код і якої в s2 нема — helper, scratch, поле, тип — дописується в s2 з позначкою :from-code, а не вигадується мовчки"
   :existing-code {:is :number-source :is-not :subject :read "цілком, без ліміту на відкриття"}
   :findings  "розділ Contract у FLOW задачі (.sdd-flow/FLOW_CONTRACT.md) — єдине місце, де привід guard-а вважається доведеним"
   :value-comes-from #{"декомпозиція ВИВЕДЕНА зі станів даних"
                       "потік даних видимий до коду"
                       "алгоритм сформульований до коду"}
   :value-does-not-come-from #{"обсяг тексту" "кількість рівнів"}
   :meter     {:invented-at-translation 0}})   ;; записи s2 з позначкою :from-code
```

## Порядок роботи

Два гейти, і обидва — слово власника. Артефакт, який власник не апрувнув, не породжує наступного.

```clojure
(def cascade-flow
  {:steps (-> (:step-1 "постановка задачі")
              (:step-2 "створення алгоритму та артефакту s1")
              (:step-3 "обговорення алгоритму, типів даних та їх мутацій, та умов виконання задач")
              (:step-4 "апрув від користувача")
              (:step-5 "створення артефакту s2")
              (:step-6 "обговорення структури коду")
              (:step-7 "апрув та написання коду"))
   :gates {:after-s1 "предмет розмови — алгоритм: чи так рахуємо, чи ті структури, чи ті умови"
           :after-s2 "предмет розмови — структура коду: декомпозиція, імена, час життя"}
   :never "починати s2 до апруву s1; писати код до апруву s2"
   :discussion-is-the-point "обидва обговорення правлять артефакт, а не код; правка артефакту після коду — це :from-code"})
```

Три читання, яких у глобальному глосарії немає, живуть проєктним блоком. Це ПРОПОЗИЦІЯ тексту

# 3 · s1 — постановка задачі та алгоритм

Тут живе те, що обговорюють: результат, правило вибору, структури з реальними типами і кроки
алгоритму — кожен із тим, що він читає і що в цих структурах міняє. Імен методів і класів тут не
буває: декомпозиція народжується вперше в s2, і саме тому s1 можна переписати, нічого не ламаючи.

```clojure
(def s1
  {:makes     "результат однією фразою, у словнику задачі"
   :criterion "правило вибору, без якого результат перестає бути собою"
   :data   {:asks  "якими структурами працює алгоритм"
            :shape "{:ключ {:type <реальний тип> :holds \"що лежить\" :from \"звідки береться\"}}"
            :rule  "тип той самий, що буде в коді — NativeParallelHashSet<int2>, int2, свій запис; схем-замінників нема"}
   :flow   {:asks  "у якому порядку, що кожен крок читає і що міняє"
            :shape "(-> (:step-N \"дія\" {:reads #{…} :writes #{…} :state \"що тепер є\"}) …)"
            :loop  "(:step-N (cond (:flow-1 \"поки умова\") (:conclusion-1 \"тіло — і знову сюди\") (:flow-2 \"інакше\") (:conclusion-2 \"вихід\")) {…})"
            :world "крок, що торкається світу, несе :world :read або :world :write — алгоритм живе між ними"}
   :exits  {:asks "умови, за яких задача не виконується" :shape "#{\"умова — привід, доведений у Findings\"}"}
   :numbers {:asks "числа задачі з формулами і порогами" :optional true}
   :must-not-hold #{"імена методів і класів" "розбиття алгоритму на частини — це робота s2"}
   :retired {:parts        "блок частин — був списком майбутніх методів, тобто копією s2"
             :boundary     "множина частин, що торкаються світу — тепер позначка :world на кроці"
             :states-chain "окремий ланцюг (-> :вхід :стан-N :вихід) — стан живе на кроці, який його досяг"}})
```

```clojure
   :retired {"одна частина — одне діло" "вимагало рівно одну зміну даних на дію → плодило порожні методи (власник, 2026-09-09)"}})
```

## Схема s1

```clojure
(def <Задача>
  {:makes     "<результат однією фразою>"
   :criterion "<правило вибору>"

   :data {:<структура-1> {:type <РеальнийТип> :holds "<що лежить>" :from "<звідки береться>"}
          :<структура-2> {:type <РеальнийТип> :holds "<що лежить>" :from "<звідки береться>"}}

   :flow (-> (:step-1 "<зняти те, з чим працюємо>"
                      {:reads #{} :writes #{:<структура-1>} :state "<що тепер є>" :world :read})

             (:step-2 "<завершена дія>"
                      {:reads #{:<структура-1>} :writes #{:<структура-2>} :state "<що тепер є>"})

             (:step-3 (cond
                        (:flow-1 "поки <умова>")  (:conclusion-1 "<тіло — і знову сюди>")
                        (:flow-2 "інакше")        (:conclusion-2 "<вихід>"))
                      {:reads #{:<структура-1>} :writes #{:<структура-2>} :state "<що тепер є>"})

             (:step-4 "<віддати результат світу>"
                      {:reads #{:<структура-2>} :writes #{} :state "<що тепер є>" :world :write}))

   :exits #{"<умова> — <привід із Findings>"}

   :numbers {:<імʼя-числа> "<формула або поріг>"}})
```

# 4 · s2 — псевдокод майбутнього класу

s2 — стиснений псевдокод майбутнього класу: те, чого в s1 немає і бути не може — декомпозиція на
методи, час життя структур і напрям кожного значення. Типи s2 не переписує: структура з s1
згадується своїм ключем. Три блоки на тип: методи, дані і хребет. На озері бракувало двох речей —
даних, які насправді потрібні кожному методу, і напряму, в якому вони течуть. Обидві живуть тут.

## 4.1 · Метод

```clojure
(def method-keys
  {:does      "ЩО метод робить, однією фразою; helper теж має :does. Метод може накрити кілька кроків s1 або бути фазою одного — межу ставить :does, не кількість кроків"
   :in        "#{ключі data} — усе, що метод ЧИТАЄ; ключ із :lives Метод або ТочкаВходу приходить параметром, ключ із :lives :прогін або :ззовні читається як поле"
   :out       "ключ data — що ПОВЕРТАЄ значенням; кілька результатів = один запис з іменем задачі; :none = нічого"
   :writes    "#{ключі data} — які структури ЗМІНЮЄ: іменник прогону (:lives :прогін) або scratch того, хто кличе (:lives Викликач, передано параметром)"
   :scratch   "#{ключі data} — структури (колекції, записи), що живуть лише всередині методу; у коді це локальні змінні, ніколи поля"
   :how       "ЯК — механізм одного діла; крапка з комою в :how означає, що тут лежить :flow"
   :flow      "порядок кроків усередині; у точці входу кожен крок несе {:calls Метод :out :ключ} (step-keys)"
   :calls     "#{методи} — helper-и, що не є кроками; виклик, який Є кроком, стоїть у самому кроці і сюди не дублюється"
   :exits     "guard-и на вході — кожен із приводом, доведеним у Findings"
   :ends-with "чим завершується, коли доробив"
   :numbers   "{:імʼя-числа \"формула або поріг\"} — усі числа, кожне з іменем із задачі; сталі геометрії сітки (6 сусідів, центр 0,0) імені не потребують"
   :note      "факт, якого не видно з решти ключів; обовʼязковий для кожного continue всередині циклу — це місця, де читач угадує"})
```



# 5 · Переклад у C# — правила розповіді

Це і є відповідь на «артефакт зрозуміліший за код». Далі «правило N» означає правило цього
розділу, «розділ N» — розділ документа. Кожне правило має `:case` з озера: `:is` — так у коді
зараз, `:should` — так має бути; цільового коду ще не існує. Усі десять виведені з одного
прогону, отже мають статус гіпотези до другого прогону з тим самим сигналом (розділ 8).

```csharp
// іменники прогону — єдині поля: те, що пишуть кілька кроків хребта
private NativeParallelHashSet<int2> _lake;
private NativeParallelHashSet<int2> _shore;

public NativeParallelHashSet<int2> Build()
{
    var numbers = ComputeRunNumbers(_order, _mapCells);
    using var middles = PlaceMiddles(numbers.MiddleReachRadius, numbers.MiddleCount);
    Grow(middles, numbers.OrderedWaterCells);
    StitchIslands();

    return _lake;
}

// що замовлення означає на цій карті
private LakeRunNumbers ComputeRunNumbers(LakeOrder order, NativeParallelHashSet<int2> mapCells)
{
    var mapCellCount = mapCells.Count();
    var orderedWaterCells = math.clamp(Mathf.RoundToInt(order.SizeFraction * mapCellCount), 1, mapCellCount);

    // карта — диск навколо (0,0): її радіус — найдальша клітина знімка
    var mapRadius = 0;
    foreach (var cell in mapCells)
        mapRadius = math.max(mapRadius, AxialMath.Distance(cell, int2.zero));

    var middleReachRadius = math.max(0, mapRadius - order.EdgeMarginTiles);
    var middleCount = Random.Range(order.MinMiddleCount, order.MaxMiddleCount + 1);

    return new LakeRunNumbers(orderedWaterCells, middleReachRadius, middleCount);
}

private readonly struct LakeRunNumbers
{
    public readonly int OrderedWaterCells;   // скільки клітин замовлено під воду
    public readonly int MiddleReachRadius;   // як далеко від центру дозволено ставити середину
    public readonly int MiddleCount;         // скільки середин кидати

    public LakeRunNumbers(int orderedWaterCells, int middleReachRadius, int middleCount)
    {
        OrderedWaterCells = orderedWaterCells;
        MiddleReachRadius = middleReachRadius;
        MiddleCount = middleCount;
    }
}
```
